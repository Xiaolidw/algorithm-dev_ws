## 1. 项目总任务、技术栈与整体架构

### 1.1 总任务

在 Gazebo 赛场中完成智能仓储机器人比赛任务：解析大模型生成的任务顺序，识别并依次抓取 5 个红/蓝物块，移动机器人携带物块进行全局规划和动态避障，将红色物块平稳放入 A 区、蓝色物块平稳放入 B 区，并在 Windows CoStudio 中实时展示赛题、摄像头、识别画面、三维场景、任务顺序、进度和状态。

核心验收目标：

- 抓取必须在夹爪接近物块后执行，物块位于两指之间，不能远距离吸附或悬浮偏置。
- 搬运期间避开墙体、固定障碍、移动障碍和未抓取物块，不能穿墙、碾压物块或碰撞后飞出地图。
- 无障碍路段应适当提速；受阻时应重规划、恢复并继续任务。
- A/B 区内放置平整、静止、完全落在区域内，不得倾斜、弹飞或碰撞已放物块。
- CoStudio 数据与 Gazebo/ROS 真实执行进度一致，摄像头与识别画面实时同步。

### 1.2 技术栈

- Ubuntu 22.04 虚拟机，ROS 2 Humble。
- Gazebo Classic：赛场、机器人、物块、移动障碍、机械臂和物理插件。
- Nav2：全局规划、MPPI 局部控制、代价地图、Collision Monitor、恢复行为。
- MoveIt 2 / 自定义机械臂 Action Server：预抓取、抓取、搬运、放置。
- Python ROS 2 节点：任务协调、任务状态机、任务进度与可视化话题。
- C++ Gazebo 插件：物块刚性跟随/释放、移动障碍物控制。
- rosbridge WebSocket：虚拟机 ROS 数据转发到 Windows `ws://localhost:9090`。
- Windows CoStudio 自定义 TypeScript/React 面板。

### 1.3 整体架构

1. 任务解析/协调层生成 5 个物块的抓取与放置顺序。
2. `mission_flow_executor_node` 维护任务状态机，依次执行预接近、精确接近、抓取、中转、送达、放置、撤离和恢复。
3. Nav2 负责底盘路径规划与避障；静态地图、物块障碍图、激光雷达和动态预测共同进入规划/安全链路。
4. 机械臂服务负责夹爪姿态与动作；Gazebo 插件在物理循环中保证夹持物块稳定跟随。
5. `/mission/execution_status` 是物理执行真值，CoStudio 以此显示实际任务进度；其他语义话题仅作题目和说明展示。

## 5. 踩坑记录与必须规避的错误

1. **不要把局部规划失败解释成“不支持斜线”**  
   差速底盘支持任意航向。应检查起点碰撞、代价地图、控制器采样和安全监控。

2. **不要再次使用 30/100 Hz ROS 服务调用来跟随物块**  
   该方案会导致 ROS 流量过大、服务饿死、DDS 回执丢失和物块竖直抖动。物块随动应留在 Gazebo 物理插件中。

3. **不要远距离吸附物块**  
   必须先导航到固定预抓取/抓取位置，检查夹爪与物块距离和姿态，再允许夹持插件接管。

4. **不要只缩短动态障碍固定等待时间**  
   `8 s` 会显得卡住，`0.5 s` 可能造成反复迎面冲突。正确方向是带滞回和方向锁存的让行状态机。

5. **不要把失败后释放在机器人旁的物块当成失败前的根因**  
   任务失败会释放携带物块，随后物块障碍图自然覆盖机器人位置。分析必须使用失败前日志/快照。

6. **不要再假设当前失败点是旧静态地图虚墙**  
   已用 Gazebo 墙体真值重建并比较地图，当前 PGM 一致，相关栅格为自由空间。除非场景再次改动，否则优先排查局部规划和动态障碍。

7. **不要在任务 active 时修改参数或重启节点**  
   这样会破坏证据链并使日志无法比较。先观察到完成/失败终态，再做最小改动。

8. **不要一次调整多个导航参数**  
   MPPI、膨胀层、Collision Monitor、动态障碍和恢复行为强耦合。每次只改一个明确原因，并保留前后日志。

9. **不要全局减小安全距离来换取“能走”**  
   机器人携带物块后外形更大，全局缩小 footprint/膨胀会重新导致撞墙、碾物块和飞出地图。应优先改目标点、拓扑中转点或障碍状态机。

10. **不要在最后一次放置后盲目倒车**  
    最后一块已改为稳定后直接结束。恢复旧逻辑可能再次碰撞或弹飞物块。

11. **不要用语义任务话题作为 CoStudio 物理进度真值**  
    面板进度必须以 `/mission/execution_status` 为准；语义话题仅用于题目文本和意图展示。

12. **不要把 Windows `localhost:9090` 当成天然指向虚拟机**  
    需确认 SSH 端口转发进程仍监听 9090、虚拟机 rosbridge 正常、CoStudio 连接类型为 Rosbridge。

13. **保留用户代码和备份，不做破坏性覆盖**
